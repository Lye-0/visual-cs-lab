# 現行の公開構成

HTML・JS・CSSの分離後の構成は [STATIC_SITE.md](STATIC_SITE.md) を参照してください。index.htmlはsrcのファイルを相対参照し、main / (root)から公開します。以下の単一HTMLやメモリ内ブラウザ試験の記載は初期設計時の履歴であり、現行の配信・検証手順ではありません。

# 設計と拡張 — v2

## 1. 永続化のない実験室

全モデルはローカルのJavaScriptで動きます。UIはモデルが返したフレーム・指標を表示し、別の答えを独自に作りません。

```text
入力 → validateParams → 計算モデル(params, lab)
                              ↓
       { frames:[title, explain, visual, stats, table], metrics, conclusion }
                              ↓
                  現在の単元の一時状態
             ┌────────────────┼─────────────────┐
             ↓                ↓                 ↓
         共通プレイヤー     図・状態・理由       条件A/Bの比較
```

画面を離れるとプレイヤーを破棄し、現在の入力・計算結果・比較・回答も破棄します。localStorage、sessionStorage、IndexedDB、Cookieによる記録は行いません。

## 2. モジュール

| ファイル | 役割 |
|---|---|
| core.js | 登録、入力制約、共通演算、フレーム定義 |
| network.js / foundations.js / security.js | 既存の計算・条件モデル |
| git.js / missions.js | 仮想Gitと総合演習 |
| catalog.js / extensions.js | 分野、テーマ、単元、コントロール、追加モデル |
| learning.js | 用語、科目、おすすめ順、理解確認問題 |
| **pedagogy.js** | 全144単元の正式な単元名、短い説明、観察点、実行可能な比較用条件、直接操作型／手順型の区別 |
| **player.js** | DOMやモデルに依存しないプレイヤー。再生、停止、シーク、速度、終了、破棄 |
| visuals.js | エスケープした文字列と数値から図・表を生成 |
| app.js | 永続化しない共通状態、レイアウト、検索、ルーティング、旧保存キーの削除 |
| pages.js | 検索主体の入口、単元一覧、科目、おすすめ順、マップ、参考資料、操作ガイド |
| workbench.js | 計算と表示の同期、入力、比較、操作案内、エラー |
| boot.js | マウス、タッチ、キーボード、入力イベント、起動 |
| style.css | ダークテーマ、レイアウト、44pxのスライダー操作領域 |

`globalThis.CSL` に登録し、build.mjs の順序で単体HTMLへ収録します。ユーザーが入力した式・CPU命令・Gitコマンドは専用パーサで扱い、`eval` や `Function` で実行しません。

## 3. プレイヤーと状態遷移

`createPlayer` は手順数・位置・再生中か・速度を保持します。実際のタイマーの登録・解除を注入できるため、Nodeテストでは仮想時計で検証できます。実装では通常の setTimeout / clearTimeout を使用します。

- 手順数が0または1なら再生しない。
- 再生中の押下は一時停止。停止中は現在位置から再開。末尾なら先頭に戻る。
- シークとステップ操作は必ず一時停止する。
- 末尾に達したら自動停止し、次のタイマーを残さない。
- 速度変更はタイマーを一つだけ作り直す。計算済みのモデル時間は変更しない。
- configure / dispose は旧タイマーを無効化する。旧コールバックが到着しても状態を変えない。

DOM側は毎フレーム図・説明・状態表だけを更新します。再生ボタンやrange入力の要素自体を置き換えないため、ドラッグ中に入力が外れません。図に固定のスクロール領域を持たせ、フレームごとの高さの差で進行バーが動き回ることも防ぎます。

## 4. 非同期計算と未反映の入力

`runCurrent` は計算の開始時に単元オブジェクトと世代トークンを保持します。画面が変わった場合や、より新しい入力が到着した場合は、古い結果を採用しません。

未反映・計算中のときは図に注意表示を重ね、シーク・比較を無効にします。エラー時は以前の図と最終指標を消し、エラーと対応方法を表示します。「モデルと根拠」は計算の成否に依存せず読めます。

通常の条件変更は再計算後の先頭を表示します。トポロジー編集と仮想Gitのコマンド追加では、利用者が行った操作の結果を確認するため末尾表示を明示的に指定できます。

## 5. 学習履歴と実験の状態を区別する

データベース、認証、ネットワーク、Gitなどの教材内に出てくるログ・履歴・保存は、その教材のモデル内容です。利用者の学習履歴ではありません。

A/B比較、再生位置、今回の実行手順、選択した回答だけはメモリ内に保持します。これらを保存・出力・再訪時に復元する仕組みはありません。表示設定もメモリ内だけです。

旧版との互換処理は起動時の `localStorage.removeItem('visual-cs-lab:v1')` だけです。読み出し・setItem・clearは使用しません。APIが利用できなくても起動を続けます。別オリジンや別ファイルの旧データを削除できるとは扱いません。

## 6. 単元を追加する

計算モデルを `CSL.register`、単元を `CSL.add` で登録します。単元には安定したid、area、track、topic、engine、controls、defaults、scope、limits、sourcesを用意します。

`pedagogy.js` の対応表には次を追加してください。

```js
{
  unit: '教科書・授業の用語で探せる単元名',
  summary: '何を変更して、どの関係を理解する実験か。',
  observe: '変更前後の、どの値や状態を比べるか。',
  exploration: {
    label: '初めに試してほしい操作',
    patch: { /* 初期条件から変える、定義済みコントロールの値 */ }
  }
}
```

比較例は表示用の文章だけでなく、実際に計算モデルへ渡すパラメーターです。初期条件と違う値が少なくとも1つ必要です。入力検証で勝手に別値へ変換されないこと、エラーなく計算できることをテストします。

結果が常に1状態の単元は `presentation:'direct'` に含めます。初期条件だけ偶然1状態になる単元は、実行結果のフレーム数でも動的に判定します。直接操作型に「1ステップで進める」といった不適切な案内を入れないでください。

確認問題、関連用語、前提単元も具体的に記載し、`tests/pedagogy.test.mjs` とブラウザテストで検証してください。

## 7. 安全性と教材としての限界

CSPで外部通信や外部スクリプト等を禁止します。単体ファイルのためスクリプト・スタイルの `unsafe-inline` を用いますが、入力のHTMLエスケープが不要になるわけではありません。

実在するネットワークやアカウントへの攻撃、認証試行、スキャンには接続しません。大きな入力や長い実行は各モデルの上限で抑えます。

乱数がある教材にはseedを設け、条件を変えて再計算できるようにします。ただしECDSAの鍵・署名のような本来の乱数値は同じ値になると保証しません。再現範囲は `MODEL_SCOPE.md` と各単元の `scope` / `limits` に記載します。

## 8. テストと配布

`npm run check` で計算・境界値・プレイヤー・保存廃止・全単元の操作例・HTTPサーバーを検証し、ビルドと一覧生成を行います。Playwrightの任意テストは `tests/browser_in_memory.py` です。通常のURL・実機のOS・各ブラウザでの確認とは区別します。

`index.html`、一覧、バージョン、README、検証報告をそろえて配布します。検証件数を前の版から流用しないでください。
