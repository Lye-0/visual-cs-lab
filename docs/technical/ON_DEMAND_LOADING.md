# 単元を選んでから読み込む

## 配信するもの

初期HTMLは検索・分類・ナビゲーション・共通プルダウン用の10本のJSと6本のCSSを参照する。全314単元の名前、要約、検索語、分類、科目との対応、各教材が参照する資料のIDは初期データにある。参考資料ページの参照件数は、教材の読み込み状況に依存させない。計算モデル、章本文、入力の定義、専用操作部品は、単元を開くまで実行しない。

`src/generated/catalog.js`は一覧用メタデータと許可された依存ファイルの一覧。`src/generated/lessons/<id>.js`は、その単元の完全な定義・章・必要な参照単元のデータ。生成されたコードは同一公開元のscriptとして読むため、`connect-src 'none'`を維持する。外部APIやCDN、eval、永続保存は追加していない。

## 正本と生成物

- `scripts/modules.mjs`：すべての正本モジュールの評価順。Nodeテスト・一覧生成は完全なモデル集合を使う。
- `scripts/delivery.mjs`：初期配信、共通描画、依存関係の定義。ビルド時にモデルを隔離したVMで評価し、エンジン・部品の登録元と単元定義を取得する。
- `src/runtime-loader.js`：ブラウザーの読み込み。単元IDは生成済みmanifestに存在するものだけ許可する。
- `src/generated/`、`index.html`：生成物。直接編集しない。

モデルや教材定義を編集したら`npm run build`を実行する。従来と違い、既存ファイル内の教材データ変更でも生成データの更新が必要になる。`npm run check`は不一致を検出し、検証中に生成物を書き換えない。GitHub Pagesはコミット済みのファイルをそのまま公開する。

## 依存関係

各単元に対して、使う計算エンジンの登録元と、全章が使う操作部品を収集する。共通ヘルパーと、その部品が使う状態モデルは`dependencies`で明示する。元のモデルを包む拡張は、元のエンジンを先にロードする。

分野内で共有する計算や部品はファイル単位で読み込むため、完全な一関数単位のtree shakingではない。最初の教材では共通描画と共通CSSも読み、以後のページでは再利用する。教材を選ぶ前に残りを一括取得する処理や、バックグラウンドで全件を読む処理はない。

共通の操作ホストは`experiences-workspace.js`に分離した。Git・数学・DBなどが、取消し・入力保持だけのためにセキュリティ教材の操作部品をすべて必要としないようにする。教材ごとのレイアウトや操作の意味は統一しない。

## 状態と障害

読み込みPromiseをファイル単位で共有し、二重登録を避ける。モデルの評価順を直列化し、依存するコードより先に実行しない。ロード済みのコードと教材定義は現在のタブ内に再利用するが、実験の操作状態は従来どおり単元移動で破棄する。

別の単元や一覧へ移動したら、以前の実験をすぐ破棄し、世代番号とURLを確認する。古いロードの完了で新しい画面を上書きしない。通信失敗時は失敗したscript/linkを取り除き、再試行できる表示にする。成功した依存ファイルを最初から実行し直さない。

## 追加・変更の手順

1. 通常どおりモデル・教材定義・操作部品を編集する。
2. 新しい部品が別ファイルの状態やヘルパーを使う場合は、`delivery.mjs`の依存関係へ追加する。
3. `npm run build`と、一覧の変更があれば`npm run inventory`を実行する。
4. `npm run check`、`npm run test:loading`、対象分野の操作検査を実行する。
5. 共通ロード経路を変えたときは全章検査も実施する。

ブラウザーテストで全単元・全章を列挙するときは`tests/lesson-fixtures.mjs`を使う。期待する全集合をNode側で取得し、ブラウザー側は実際の遅延読み込みで確認する。検査の都合でブラウザーへ全教材を先読みさせない。

## 測定の読み方

ファイルサイズの比較は非圧縮のソースサイズ。実際の転送量は圧縮・キャッシュ・配信環境に依存する。ローカルの起動時間はインターネット上の実ユーザーのLCPやINPを保証しない。測定結果は[検証記録](../verification/ON_DEMAND_REVIEW.md)に条件を付けて残す。
