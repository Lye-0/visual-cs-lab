# 共通プルダウン

`src/custom-select.js` と `src/custom-select.css` が、サイト内の単一選択欄を独自のcombobox/listboxとして表示する。一覧、新しい教材、旧詳細実験、再生速度を同じ仕組みで扱う。

## 値と表示の分担

教材は従来どおり、ラベルと `select` / `option` を生成する。元の要素はフォームの値・検証・既存のイベント処理のために残すが、画面、Tab移動、アクセシビリティツリーから外し、ブラウザ標準の選択メニューを開かせない。利用者には隣の独自ボタンを提示する。

確定時に元の `selectedIndex` を更新し、値が変わったときだけ `input` と `change` を各一回送る。既存の `selectOption` やフォームのresetも表示へ反映する。教材の計算や即時反映／実行ボタンで確定という区別は変更しない。

DOMの追加・置換・候補変更はMutationObserverで同期する。観測対象の属性へ同じ値を書き続けない。無効状態の同期を含め、変更があるときだけ書き込む。外部から値だけを代入し、イベントもDOM更新も発生させない処理では `CSL.selectUI.refresh()` を呼ぶ。

## 操作と配置

- クリック、ラベル、Enter／Space、矢印キーで開く。
- 上下矢印、Home／End、先頭文字で候補を移動し、Enter／Spaceかクリックで確定する。無効な候補は選ばない。
- Escape、Tab、外側のクリックで閉じる。移動中の候補は確定するまで値を変えない。
- フォーカスはcomboboxに置き、`aria-expanded`、`aria-controls`、`aria-activedescendant`、候補の `aria-selected` を同期する。
- 候補一覧はPopoverのトップレイヤーへ置く。利用できない環境では固定位置の要素として表示する。画面端とvisualViewportに合わせて幅・高さ・上下位置を調整する。
- 長い一覧は一覧内でスクロールする。教材やページのスクロール量を独自に加速しない。
- 教材の再描画で選択欄が置換された場合、同じIDの新しい欄へフォーカスを戻す。ルートが変わった場合は追いかけない。削除された欄のボタンや候補一覧を残さない。

ラベルや選択肢は `textContent` で組み立てる。外部ライブラリ、外部通信、永続保存を追加しない。現在の教材は単一選択のみであり、複数選択リストを追加するときは操作とARIA契約を別途設計する。

## 配信と検証

検索画面にも必要なので初期配信へ追加する。初期配信は10 JS・6 CSS、今回の非圧縮ファイル合計は660,327 bytes。単元モデルの必要時読み込みは維持する。スクロールバー用CSSは引き続き最後に読み込む。

`node tests/custom-select-browser.mjs` は1440・390・320pxで、実際の教材とフォームの操作契約を検査する。`BROWSER` はchromium／firefox／webkit。`ALL_SELECTS=1` を加えると314単元・588章を巡回して選択欄の置換漏れも確認する。成果物はGit無視対象の `review-output/custom-select/`。

2026-09-26の確認では、各ブラウザ45操作検査が成功し、Chromiumの全章巡回で135個の選択欄の置換を確認した。WebKitの全章表示検査は588章×3幅でエラー・表示候補0。Nodeの既存3,947テストも成功。PCと320pxのHTTP方式の候補一覧を目視確認した。支援技術のARIA状態とキーボードは検査したが、実機のスクリーンリーダーによる読み上げ試験とは区別する。
