# 教材の入力を自動反映する

数値、選択肢、チェック、文字列、コードの条件変更は、反映ボタンを必須にせず結果へ反映する。通常の教材、専用作業台、旧詳細画面に適用する。再計算ボタンは再実行の入口として残す。

## 入力条件と実験内の操作

条件の変更と、順序そのものを学ぶ行為を区別する。座標・係数・行列・容量・通信設定などは自動反映する。パケット送信、資源取得、スタックへの追加、行基本変形、Gitのadd/commit、時刻を進める操作などは、入力しただけで実行しない。

`live-input.js` の `X.liveInput` が遅延実行、IME変換、取消し、フォーカスと選択位置、開いた説明を管理する。チェック・選択・スライダーは次のイベント処理で、数値・文字列は通常200ms、複数行編集は450msの入力休止で反映する。旧readerは数値50ms、文字列250ms、コード450ms。計算時間は別に必要。

`X.liveForm` は純粋な条件計算フォームに使う。送信・追加・書込みなどの操作フォームへ一律に付けない。`X.liveWorkspace` は `X.liveActions` に明示した条件更新だけを接続する。動的な品物の入力には `item:*` のような限定した指定を使う。`config.action` はフィールドを読むだけのアクション生成関数であり、副作用を入れない。条件を反映した直後に別の対象や次の操作を選んだ場合は、保留中の条件を先に処理する。リセット・取消し・画面移動は保留処理を無効化する。

通常の計算教材は入力のたびに世代番号を更新し、遅い古い計算が新しい結果を上書きしない。不完全な数値・構文は編集できるままにし、有効な入力へ戻れば自動復帰する。途中の無効な入力を初期値へ黙って戻さない。通常教材でも直前の結果を残し、入力欄の近くで更新中・入力エラーを示す。前の結果は最新の計算結果とは扱わず、更新中は図や手順の操作を無効にする。新しい結果が完成してから差し替え、空の結果欄を挟まない。SQLプレビューと旧詳細画面にも同じ方針を適用する。

## SQLの自動プレビュー

SQL作業台は確定済みの表のコピーへ実行し、入力に合わせて結果をプレビューする。編集中に同じUPDATEを繰り返し表へ適用しない。「表への変更を確定する」で初めて作業台の表を更新し、次の編集の出発点にする。例を選ぶ、表をリセットする、取消す場合もプレビューを作り直す。外部DBへは接続しない。

## 確認

`node tests/live-input-browser.mjs` は数値・連続入力・無効値復帰・文字列・座標・専用設定・動的な品物・コード・旧画面・模擬IME・遅い計算・移動時取消し・直後の操作順・SQLを検証する。2026-09-26にChromium・Firefox・WebKitで各34件成功。手順を持つ操作の引数を編集しても、自動でスタックに追加されないことも確認する。

広域検証はWebKitで全588章×3幅の1,764表示が成功（実行エラー・表示候補0）、専用作業台など22スクリプトが成功。後続の順序・フォーカス調整は上記の追加検証とGit69件、数学75件で確認した。旧readerの回帰27件は手動反映を期待する旧テストを自動反映の仕様へ更新して成功。これらは全入力の組合せの保証ではない。

この仕組みは `experiences-view.js` の後、専用作業台の前に必要時読み込みする。初期画面へ全教材を読み込む変更や、学習履歴の永続保存は追加しない。

更新の安定性は `tests/smooth-updates-browser.mjs` で別に確認する。c04-traceの11→12変更へ220msの計算待ちを注入し、requestAnimationFrameごとに内容の有無、結果欄の高さ、入力欄の位置、ページのスクロール位置を測る。開いた導出、無効値からの復帰、旧readerの図の保持も対象。
