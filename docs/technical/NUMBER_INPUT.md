# 共通の数値入力

`number-input.js` と `number-input.css` は教材の数値入力を、直接入力欄と「−」「＋」の組にする。ブラウザ標準のスピナーは非表示。元の `input[type=number]`、ID、ラベル、フォーム値、必須入力、上下キーを保つ。

- 指定された `step`、`min`、`max` に従う。通常の増減はブラウザの `stepUp` / `stepDown` を利用し、小数の誤差を独自の足し算で増やさない。
- `step="any"` は直接入力の精度を制限しない。ボタンだけは1ずつ変え、範囲に収める。その刻みをボタンのtitleにも示す。
- 上下限、disabled、readonlyをボタンの状態へ反映する。値が変わった場合だけinputとchangeを各一回送る。
- マウス／タップで増減した後は数値欄へフォーカスを戻す。キーボードでボタンを押した場合は、続けて押せるようフォーカスを保つ。境界でボタンが無効になった場合は入力欄へ戻す。
- 動的に作られる教材にも適用する。MutationObserverの同期は同じ属性の書込みを繰り返さない。DOMもイベントも更新しない値の代入は `CSL.numberUI.refresh()` で同期できる。
- 選択メニュー同様の配色を使い、狭い画面では増減ボタンを44px幅にする。旧詳細画面のスライダーと数値欄は狭幅で縦に並べる。

教材の共通モジュールとして必要時に読み込む。計算モデルや学習履歴の保存は追加しない。`reader-responsive.css` の配置指定は `.reader` で範囲を明示し、後から基本CSSが来ても狭幅の縦配置を維持する。

検証: `node tests/number-input-browser.mjs`。Chromium・Firefox・WebKitで各24件（1440/390/320px）、小数、上下限、連続キー操作、イベント回数、readonly/disabled、リセット、空欄、タップ、旧詳細画面を確認した。WebKitでpointerdownの取消しがタップを妨げたため、増減ボタンではその取消しを使わない。全588章×3幅の表示検査も実行エラー・表示候補とも0。実際のスマートフォン実機の検査とは区別する。
